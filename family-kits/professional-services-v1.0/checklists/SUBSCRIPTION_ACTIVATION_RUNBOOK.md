# Professional Services — Subscription Activation Runbook

**Uso:** soltanto quando l'utente decide di acquistare gli abbonamenti

## A. Prima

- [ ] Beauty archiviata.
- [ ] Professional 1.0 archiviata.
- [ ] Home Services preparata.
- [ ] mese intensivo scelto.
- [ ] tempo disponibile.
- [ ] GitHub accessibile.
- [ ] nessun QUADRA Lovable creato.

## B. Acquisto

- [ ] verificare prezzi e funzioni correnti;
- [ ] attivare piano previsto per un mese;
- [ ] Lovable Pro, non Business salvo nuova decisione;
- [ ] niente annuale;
- [ ] niente ricarica automatica indesiderata;
- [ ] registrare attivazione e rinnovo;
- [ ] salvare ricevute.

## C. Lovable

- [ ] workspace corretto;
- [ ] ID;
- [ ] piano;
- [ ] saldo;
- [ ] accessi;
- [ ] niente database;
- [ ] niente connector non necessari.

## D. GitHub

- [ ] creare `quadra-studio-START`;
- [ ] inserire documenti;
- [ ] branch;
- [ ] verificare sync;
- [ ] non creare BUSINESS vuoto.

## E. Avvio

- [ ] STATUS `IMPLEMENTATION_AUTHORIZED`;
- [ ] comando utente registrato;
- [ ] usare prompt START;
- [ ] allegare docs;
- [ ] niente backend/auth/upload;
- [ ] salvare ID e risposta;
- [ ] registrare consumo.

## F. Guardrail crediti Professional

```text
30% START initial
20% START structural corrections
15% START approved polish
20% BUSINESS expansion
10% BUSINESS corrections
5% buffer
```

Percentuali interne, non previsione.

- [ ] consumo giornaliero;
- [ ] niente prompt vaghi;
- [ ] stop Lovable durante audit;
- [ ] niente redesign dal buffer.

## G. Stop

- backend;
- auth;
- upload;
- identità cambiata;
- fake proof;
- raccolta dati eccessiva;
- dependency;
- scope drift;
- consumo anomalo;
- modifiche simultanee.
