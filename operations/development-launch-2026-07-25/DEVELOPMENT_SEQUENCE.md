# Tretnix — Development Sequence

## Obiettivo mensile

```text
1. RITO START
2. RITO BUSINESS
3. QUADRA START
4. QUADRA BUSINESS
5. NODO START
6. NODO BUSINESS — stretch
```

## Ciclo per ogni START

```text
specification
→ repository
→ Lovable build
→ sync
→ stop Lovable
→ Impeccable read-only
→ manual finding approval
→ approved polish
→ Codex audit/consolidation
→ verification
→ freeze/tag
```

## Ciclo per ogni BUSINESS

```text
canonical START
→ completed inheritance contract
→ derived BUSINESS repository/project
→ Lovable expansion
→ stop Lovable
→ Codex consolidation
→ Impeccable parity review
→ approved corrections
→ comparative QA
→ freeze/tag
```

## Regola di priorità

Un deliverable non passa allo stadio successivo se:

- il precedente non è verificato;
- il diff non è revisionato;
- il working tree non è pulito;
- i limiti non sono documentati;
- il freeze non è registrato.

Home BUSINESS non deve ridurre la qualità degli altri cinque deliverable.
